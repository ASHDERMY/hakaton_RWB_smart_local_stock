# Архитектура Smart Local Stock

## Слои приложения

Streamlit UI → расчётный слой `engine.py` → слой данных `database.py` → SQLite.

## Основные сущности

- `pickup_points` — Anchor, обычные ПВЗ и Hub; новые точки можно добавить из UI.
- `sellers` — продавцы, поставляющие товары в Hub.
- `supplier_deliveries` — входящие поставки продавцов, ожидающие приёмки или уже принятые.
- `products` — каталог SKU и объём единицы товара.
- `inventory` — физический остаток, резерв и поступление в пути.
- `orders` — заказы, статусы, источник, маршрут, оценка затрат и связь с партией.
- `mesh_batches` — ожидающие и отправленные партии для направления Anchor → конкретный обычный ПВЗ.
- `stock_movements` — журнал приёмки, резервирования, снятия резерва, отправки, поступления, выдачи и возврата.
- `returns` — возвраты и результат проверки состояния товара.
- `incidents` — логистические инциденты, сформированный план действий и признак изменения маршрута.
- `settings` — редактируемые параметры модели с классификацией и пояснениями.

## Жизненный цикл Mesh-заказа

1. При создании заказа проверяется доступность товара в Anchor.
2. При наличии запаса создаётся/используется ожидающая партия; товар резервируется.
3. Система считает реальное число заказов и суммарный объём партии.
4. При достижении целевой загрузки, лимита вместимости или 5 часов выполняется экономическое сравнение Mesh и Hub.
5. При выборе Mesh все заказы партии переводятся в статус «В пути», резерв списывается из Anchor, стоимость рейса распределяется по заказам.
6. При выборе Hub резервы переносятся из Anchor в Hub; дальнейшее движение обрабатывается стандартным жизненным циклом Hub-заказа.
7. При недостатке запаса на Hub партия блокируется, резервы Anchor сохраняются, оператор может пополнить Hub и повторить проверку.

## Сохранность данных и миграции

При запуске `init_db()` создаёт отсутствующие таблицы и добавляет новые столбцы в существующую SQLite-базу через миграционные проверки. Исторические заказы не переназначаются и не пересчитываются. Новые таблицы и поля добавляются без удаления существующих пользовательских данных.

## Границы MVP

SQLite предназначена для локальной разработки и демонстрации. Для постоянной облачной эксплуатации потребуется внешнее постоянное хранилище. Выбранная локальная архитектура SQLite сохраняется до отдельного согласования изменения.
