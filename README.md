# Smart Local Stock

Рабочий учебный MVP для моделирования локального хранения товаров в опорных ПВЗ (Anchor) и выбора логистического маршрута Hub/Mesh.

## Запуск (Windows / PowerShell)

```powershell
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
streamlit run app.py
```

При первом запуске схема SQLite создаётся автоматически. Для тестового набора используйте кнопку «Загрузить демонстрационные данные». Она добавляет только отсутствующие записи и не перезаписывает существующие товары, точки и остатки.

## Реализовано

- Каталог SKU и сеть точек (Anchor, обычные ПВЗ, Hub).
- Приёмка товара, резервы и журнал движений запасов.
- Создание заказов с проверкой доступных остатков.
- Реальная очередь Mesh-партий по паре Anchor → обычный ПВЗ.
- Подсчёт фактического числа заказов и суммарного объёма товаров в партии.
- Проверка целевой загрузки, ограничений 130 заказов / 1 500 л и максимального ожидания 5 часов.
- Сравнение стоимости Mesh по фактическому размеру партии с альтернативой Hub.
- Перевод партии на Hub, если Mesh экономически невыгоден; блокировка перевода, если на Hub недостаточно запаса.
- Отправка Mesh-партии и распределение стоимости рейса по заказам партии.
- Управление статусами, отмена заказов, возвраты и логистические инциденты.
- Расчётная финансовая сводка по заказам.
- Сценарный калькулятор экономики четырёх сторон: маркетплейс, владелец ПВЗ, продавец и покупатель; все вводимые тарифы помечены как гипотезы.
- Калькулятор пополнения Anchor по формулам доступного и целевого запаса; средний спрос D вводится оператором и не является ML-прогнозом.
- Автоматическая проверка ожидающих партий при каждом обращении к приложению (не фоновый планировщик).

## Интерактивная карта сети

- Отдельный раздел «Карта логистики» показывает региональный СЦ WB Казань (Зеленодольск), проектный Anchor и городские ПВЗ Йошкар-Олы.
- Для выбранного заказа отображаются источник, ПВЗ назначения, дорожное расстояние и расчётное время (если доступен OSRM).
- Дорожная геометрия строится по открытой дорожной сети OpenStreetMap через OSRM; при недоступности сервиса карта показывает схему и не выдумывает километраж/ETA.
- Красный маркер транспорта перемещается по маршруту через ручной слайдер/шаги. Это демонстрационная симуляция, а не GPS-трекинг WB.
- СЦ Зеленодольск показан как подтверждённый объект WB; Anchor — проектная точка, городские ПВЗ — ориентиры для демонстрации, адреса и координаты требуют сверки по официальной карте WB.
- Карта использует pydeck, requests и требует доступа к картографическим тайлам и OSRM.

## Как работает очередь Mesh

1. Если в Anchor достаточно запаса и заказ укладывается в ограничения, товар резервируется, а заказ попадает в ожидающую партию.
2. Партия группируется по направлению Anchor → конкретный обычный ПВЗ.
3. При достижении целевой загрузки (по умолчанию 80 заказов), предела вместимости или истечении 5 часов система принимает решение.
4. Полная расчётная стоимость Mesh на заказ: стоимость рейса / фактическое число заказов + переменные расходы на заказ.
5. Если Mesh дешевле Hub, партия отправляется. Иначе заказы переводятся на Hub при наличии там необходимого запаса.
6. Если запаса Hub недостаточно для всех заказов партии, партия получает блокирующий статус; после пополнения Hub её можно проверить повторно.

5 часов — проектное ограничение ожидания партии, а не подтверждённый SLA RWB. Отдельный фоновый планировщик не используется: проверка выполняется при создании заказа, при каждом обращении/перерисовке приложения и по команде оператора в разделе «Партии Mesh».

## Данные и допущения

- Стоимость рейса, Hub и переменных расходов — гипотезы модели, не подтверждённая внутренняя себестоимость RWB.
- Целевая загрузка 80 заказов — проектное допущение; ограничения 130 заказов и 1 500 л — заданные параметры модели.
- Публичные тарифы продавца нельзя подменять внутренней себестоимостью логистики маркетплейса.
- Исторические заказы сохраняют свои рассчитанные затраты. Новая логика партий применяется к новым заказам.
- SQLite хранит локальные данные в `data/smart_local_stock.db`. Файл базы данных не следует удалять при обновлении кода.

## Публикация

Для Streamlit Community Cloud укажите `app.py` как основной файл. Локальная SQLite-база не является надёжным постоянным хранилищем в облачной среде; для постоянной публичной эксплуатации потребуется внешняя БД. SQLite сохраняется для локального MVP в соответствии с выбранной архитектурой.
